## 0. 一句话

**SODA-A 的切块必须用"网格 + 补一块贴住右/下边缘的瓦片、并丢弃跨边界框"（策略 P7）。**
理由是实测出来的：不补边缘瓦片时，"丢框率"高达 **21.07%**，而其中**只有 4.03 个百分点是真的跨边界**，
其余 **17 个百分点纯粹是瓦片网格没盖住图幅的右/下边条**造成的几何性丢框。

---

## 1. 这一步解决什么问题

`L0_VERDICT.md` 只给了"SODA-A（800 裁块，不缩放）"一行（中位 12 px、每瓦片 20.7 目标），
**没有定下切块策略**。而策略直接决定**逐桶框数**，也就是论文的尺寸分层结论。
本课题的核心因变量是"**效应随目标尺寸如何变化**"，任何会系统性改变各桶框数的策略选择
都是**分析自由度**，必须在看结果之前定死。

## 3. ★ 七种策略的实测对照（全部只用标注）

定义（都 800×800、原生不缩放、无 padding）：

| 策略 | 网格 | 框归属 | 框处理 |
|---|---|---|---|
| P1 | 纯网格 | 必须完整落在某瓦片内 | 丢弃跨边界框 |
| P2 | 纯网格 | 按框中心（中心落边条时归最近瓦片） | 不裁剪 |
| P3 | 纯网格 | 同 P2 | **裁剪**到瓦片内 |
| P4 | 纯网格 | 最大交叠面积瓦片 | 不裁剪 |
| P5 | 步长 400 | 必须完整落在某瓦片内 | 丢弃跨边界框 |
| **P6** | **网格 + 补边缘瓦片** | 按框中心 | 不裁剪 |
| **P7** | **网格 + 补边缘瓦片** | 按框中心 | **丢弃跨边界框** |

实测（全部已排除 `ignore`；"跨边界"= 框没有完整落在其归属瓦片内）：

| 策略 | 瓦片 | 框 | 框/瓦片 | 中位 px | 4–16 px | 跨边界率 | 丢框率 | 空瓦片 |
|---|---|---|---|---|---|---|---|---|
| P1 | 42,514 | 688,328 | 16.19 | 11.900 | 68.06% | 21.07% | **21.07%** | 26 |
| P2 | 42,514 | 872,069 | 20.51 | 11.954 | 67.85% | 21.07% | 0 | 1 |
| P3 | 42,514 | 723,803 | 17.03 | 11.927 | 67.71% | 21.07% | 17.00% | 23 |
| P4 | 42,514 | 872,069 | 20.51 | 11.954 | 67.85% | 21.07% | 0 | 1 |
| P5 | 137,925 | 759,244 | 5.50 | 11.986 | 67.35% | 12.94% | 12.94% | 19 |
| **P6** | **60,280** | 872,069 | **14.47** | 11.954 | 67.85% | **4.03%** | 0 | 1 |
| **P7** | **60,280** | 840,947 | **13.95** | **11.878** | **68.40%** | **3.57%** | **3.57%** | 2 |

按官方 split 的瓦片数（P6/P7）：**train 25,613 / val 13,816 / test 20,851**。

### 3.1 ★ P2 / P4 是**错的**，虽然它看起来"框数守恒"

P2/P4 让 42,514 个瓦片装下了全部 872,069 框，框/瓦片 **20.51**，跟 L0 报的 20.7 几乎一样
——**看起来最"对"**。但它把 **21.07% 的框（183,741 个）塞进了"最近的瓦片"**，
而这些框的中心可能离该瓦片边缘还有几百像素。
⇒ **框数守恒，空间对应关系被破坏**。用它当训练标签，会让检测器把框回归到错误的位置。
**排除。**

### 3.2 P1 是错的，而且错得**看不出来**

P1 的丢框率 21.07% 表面上像"跨边界丢框"的正常代价。但对照 P6/P7 就能拆开：

```
纯网格的跨边界率          21.07%
补边缘瓦片后的跨边界率     4.03%     ← 真实的"框跨边界"只有这么多
差                        17.04 pp  ← 全是"图幅右/下边条没被任何瓦片覆盖"
```

原因很具体：图幅如 4800×2744，`y` 方向的完整 800 瓦片只能放到 `y=1600`（覆盖到 2400），
剩 **344 px 的条带完全没有瓦片**（占该图面积 12.5%）。这一条带里的框 100% 被丢掉。

⇒ **P1 的丢框是几何性的，不是统计性的**，且**偏向大目标**（大目标更容易越界）。
在"效应随尺寸变化"的研究里，这直接污染自变量。**排除。**

### 3.3 P3 也不该用（裁剪会改尺寸）

P3 裁剪后 6+ 桶的框数明显变化（`2-4` 桶 8,258 → **8,131**，而 `0-2` 桶 36 → **698**）：
裁剪把跨边界框切小，**短边被改变 ⇒ 桶归属被改变**。本课题研究的就是桶归属。**排除。**

### 3.4 P5（50% 重叠）没有收益

瓦片数从 42,514 涨到 137,925（+224%），丢框率只从 21.07% 降到 12.94%。
因为在"按中心归属、每框只算一次"的设定下，重叠**不减少跨边界**，只增加瓦片数。
**排除。**

## 4. 采用 **P7**，以及为什么不是 P6

P6 与 P7 的差别只有一处：**跨边界的 4.03% 框是"保留（可能溢出瓦片几像素）"还是"丢弃"**。

选 **P7（丢弃）**，理由：

- 标准检测管线期望标签落在图像内；溢出框会被各实现以不同方式裁剪，
  **裁剪会改变短边 ⇒ 改变桶归属**（与 §3.3 同一个问题）。
- P7 的代价只有 **3.57%**，且对分布的影响极小：
  中位 11.954 → **11.878 px**（差 0.076 px），4–16 px 占比 67.85% → **68.40%**。
- 相比之下 P1 丢 21.07% 时中位是 11.900 —— 两个"丢框"方案的边际统计几乎一样，
  但 P7 的丢框率只有 P1 的 **1/5.9**，且是在**100% 覆盖**下丢的，不是几何盲区。

**P7 的确切定义（实现时必须一模一样）**：

```
对每张图 (W, H)：
  xs = [0, 800, 1600, …]  直到 ≤ W-800；若最后一块 ≠ W-800，追加 W-800
  ys = 同理
  瓦片 = xs × ys                      # 100% 覆盖，瓦片间只可能在边缘条带重叠
对每个框 b（已排除 ignore）：
  找唯一一个满足 b 完整落在其中的瓦片；找不到 ⇒ 丢弃该框
  否则记到该瓦片，坐标原样保留（不做任何裁剪）
```

## 5. `ignore` 政策（预注册）

1. **训练与评测的 GT 一律排除 `category_id = 9`**（6,673 框，中位 49.97 px，是大区域）。
2. **不实现 COCO 的"ignore 区域内检测不计 FP"语义** —— 实现复杂度高、且会引入
   一个未被预注册的评测自由度。作为**已知局限**写进论文：
   "被 `ignore` 标注覆盖的区域在评测中会被计为假正例（FP）"。
3. 需要报告的量：被选中的评测瓦片里，`ignore` 框的**中心落在瓦片内**的数量
   （作为该局限的规模指标，逐维交代）。这一步在瓦片选定后跑，属于**报告**，不参与判决。

## 6. 瓦片预算与选取规则（预注册）

对齐 AI-TOD 的规模（POOL 2,804 / TRAIN_FRAC 0.75）：

| 集合 | 来源 | 瓦片数 | 依据 |
|---|---|---|---|
| 训练 | 官方 **train** 的 25,613 个瓦片 | **2,103** | = AI-TOD 训练图数 |
| 评测切片 | 官方 **val** 的 13,816 个瓦片 | **500** | 目标 ≈ AI-TOD 评测切片的 `n_gt = 7,304`（500 × 13.95 ≈ 6,975） |
| 最终确认（不用） | 官方 **test** 的 20,851 个瓦片 | — | 与 AI-TOD 同纪律：test 只在最终确认时碰一次 |

**选取规则：`md5(瓦片标识)` 确定性乱序取前 N**，瓦片标识 = `<split>/<源图名>__<x>__<y>`。

为什么不是"前 N 个"：`DIOR_L1_PREREG.md` §7.4 已实测，数据集归档普遍有**块结构**
（DIOR 前 1000 张每图 6.02 目标 / 中位 24 px，整档是 5.56 / 28 px）。
md5 乱序与归档顺序无关、可审计、可复现，是四种方案里与整档偏离最小的（+2.7 pp）。

**预算的实验单位是瓦片，不是源图。** 2,103 个训练瓦片从 1,067 张 train 图里均匀抽
（平均每图 ~2 个瓦片）⇒ 预计覆盖约 **900 张不同的源图**。
覆盖的具体源图数在选定后**报出**（不参与判决），因为同一源图的瓦片空间相关，
这是必须写进论文的局限。

## 7. 事先声明的局限（无论结果如何都要写进论文）

1. **瓦片间可能空间相关**：同一源图的瓦片共享场景，不是独立样本。抽样已尽量打散
   （按瓦片而非按图抽），但相关性不能归零。
2. **`ignore` 区域按 FP 计**（§5.2）。
3. **SODA-A 的绝对 mAP 不可与 AI-TOD 横向比**：图像来源、传感器、场景、类先验都不同，
   只能主张"**跨数据集、同尺度区间**的复现"。这条与 `L0_VERDICT.md` §3.2 代价③一致。
4. **类别被合并为单类**（AI-TOD 8 类合 1，SODA-A 10 类合 1）；两边各自的类先验差异极大
   （SODA-A 的 `small-vehicle` 占 59.86%）。
5. **P7 丢掉 3.57% 的框**，且偏向大目标（大目标更容易越界）。已在 §4 量化其对中位的影响（0.076 px）。

### 9.1 ★ 抓到扫描脚本一处**字段名与实现不符**（不是数字分歧）

扫描脚本报的 `empty_tiles = 2`，其实现是
`tiles_per_img.append(len(bucket))` 之后 `sum(1 for x in tiles_per_img if x == 0)`。
`bucket` 只装**收到过框**的瓦片，所以 `x == 0` 是「**一个框都没落到的图**的张数」，不是空瓦片数。
⇒ 已在 `soda_tile.py` 的 `AUDIT` 里把该字段改名为 `img_no_box`（审计值仍 = 2），
真空瓦片**另测**并另报：**31,646 / 60,280（52.50%）**。这是新测的量，不是对旧值的修正。

**为什么这条要紧**：52.5% 的瓦片是空的，说明框在空间上高度聚集。若当初拿 `empty_tiles`
去估"稀疏度"，会低估两个数量级。凡是"字段名暗示了实现没做的事"，都要当成 bug 处理。

### 10.1 2026-10-16 22:15 —— 补齐**训练期 val** 的口径（§6 只冻结了"训练 2,103"，没写 val 从哪来）

**问题**：AI-TOD 的主协议是 `POOL=2804` + `TRAIN_FRAC=0.75`，`tv_sweep.build_view` 里

```python
n_tr = max(1, int(round(len(files) * train_frac)))
part = "train" if idx < n_tr else "val"
```

即 **2,103 训练 + 701 留作训练期 val**（ultralytics 用那 701 张的 mAP 选 `best.pt`）。
§6 只写了"训练 = 2,103 瓦片"，**没写那 701 从哪来**。若不补，SODA 侧只有两条路：

| 走法 | 后果 |
|---|---|
| 训练期 val 用官方 `val` 的 500 个**评测瓦片** | 评测切片同时被用于选 `best.pt` ⇒ 比 AI-TOD 多一层泄露，且与 §5.1「评测与训练用不同 split」矛盾 |
| 把 2,103 再切 25% | 训练集只剩 **1,577**，与 AI-TOD 的 2,103 **不可比** —— 而"可比"正是本文件存在的理由 |

**采用的走法**：把训练池从 2,103 扩到 **2,804**（= AI-TOD 的 `POOL`），
按 §6 的 md5 乱序取前 2,804 个 `train` 瓦片：

```
pool_train = pick("train", 2804)
sel_train  = pool_train[:2103]        # 训练，**逐字节等于** §9.2 记录的那 2,103 个
val_hold   = pool_train[2103:2804]    # 701 个训练期 val，只用于选 best.pt
```

**为什么这不是改规格**：`pick` 是按 md5 全序排序后取前 N，所以
`pick("train", 2804)[:2103] ≡ pick("train", 2103)` —— §9.2 记录的选定集合
（2,103 瓦片 / 27,939 框 / 中位 12.297 px / 逐桶框数）**一个数都没变**（§10.2 实测复核）。
变的只有两件事：`SODA_TILE_SEL.json` 从 2,603 条变 3,304 条；覆盖源图从 941 张变 1,000 张。

**新增的事先声明局限**（补进 §7 的语境）：

6. **训练期 val 取自 `train` split**（与 AI-TOD 同构），而评测切片取自 `val` split。
   两者来源不同 ⇒ 训练期的早停判据与最终评测**不同分布**。AI-TOD 主协议有同样的性质
   （val 与 scan 都取自同一留出池），所以本设计与之**可比**，但**不是更好**。

**这一条不改 §3 的任何判据**，只补 §6 未定的一个自由度。`soda_tile.py` 里以
`N_POOL_TRAIN = 2804` 实现，并加了一条断言 `pool_train[:N_TRAIN] == sel_train`。
