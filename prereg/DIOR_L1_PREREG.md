- `Δ = mAP_A(ref) − mAP_B0(ref)`

## 3. 判据（结果产生前写定，不许事后改判）

### 3.1 主终点：ref 干净端上的 `Δ(A−B0)`

| 判据 | 阈值 | 含义 |
|---|---|---|
| **① 动态范围** | 两臂都满足：`R_arm ≥ 0.010` **且** `mAP_arm(heavy) > 0.010` **且** `R_arm ≥ 5 × SD_real(arm)` | 端点没贴地板、值得测 |
| **② 效应量** | `\|Δ\| ≥ 0.005` **且** `SNR_imp ≥ 2` | 效应在同一量级且可测 |
| **③ 地板稳定** | 两臂 `SD_real(arm) ≤ 0.20 × \|Δ\|` | 退化实现噪声相对效应可忽略 |

**通过 = ① ∧ ② ∧ ③** ⇒ 放行 L2（全量 4 臂 × 6 种子 × 16 条件）。

### 3.2 `SNR_imp` 的定义与它的假设（必须写进报告）

`MDE_imp = t_crit(df=5) × SD_imp / √6 = 2.571 × 0.00141 / 2.449 = 0.001480`
`SNR_imp = |Δ| / MDE_imp`

`SD_imp = 0.00141` = **AI-TOD 实测的 ref 端种子水平 SD**（`_mde_check.py` §2.2），
因为 **1 个种子无法估计种子 SD**。这是一条**导入的噪声尺度假设**：

- 它在 AI-TOD 的协议下实测得到，本机同一卡、同一 YOLOv8n、同一 30 epoch；
- 但 DIOR 的目标密度与尺度不同 ⇒ **不能假设它逐位成立**；
- ⇒ 报告里必须同时给出 `SD_real`（真实测到的下界），并声明 L2 的 6 种子会**事后校正**此值。

### 3.3 判决表

| 触发 | 判决 | 性质 |
|---|---|---|
| ①a∧①b∧②∧③ | **放行 L2** | 协议可移植 + 效应可测 |
| `SNR_imp ∈ [1,2)`（其余满足） | **不算失败**：种子加到 12 再判（SNR ∝ √n ⇒ ×1.41） | 功效不足，可修 |
| `SNR_imp < 1` | **停** | 功效不足；报告须写"主终点在 DIOR 上不可测" |
| ①a 不满足（`R < 0.010` 或 `mAP(heavy) ≤ 0.010`） | **停** | 协议失败；报告须写"端点无动态范围" |
| ①b 不满足（`R < 5×SD_real`） | **先查测量管线** | 实现噪声淹没两端差，不是科学结论 |
| ③ 不满足（`SD_real > 0.20×\|Δ\|`） | **先查测量管线** | 地板相对效应不稳，不是科学结论 |
| `\|Δ\| < 0.005` 但 SNR ≥ 2 | **停，且这是真否证** | 现象在新数据集上确实更弱 |

**① 已拆成两个子判据**：①a = 真·动态范围（`R ≥ 0.010` 且 `mAP(heavy) > 0.010`）；
①b = 两端差相对实现噪声（`R ≥ 5×SD_real`）。拆开是为了让"协议失败"与"仪器噪声"
两条完全不同的结论不互相冒充。

**③ 的 `SD_real` 定义（已实测可算）**：ref 条件用 **3 个不同的 `tag_base`**
（`l1X_` / `l1Y_` / `l1Z_`）各评一次 ⇒ 同一模型、同一条件、不同退化实现 ⇒
三次结果的样本 SD（ddof=1）即"实现噪声"地板。

#### 判决分支的**执行顺序**（代码里写死，不许改序）

```
if   ①a∧①b∧②∧③          → 放行 L2
elif not ①a              → 协议失败（端点无动态范围）
elif not ①b              → 测量异常（噪声淹没两端差）⇒ 先查管线
elif SNR < 1             → 功效不足
elif SNR < 2             → 不算失败，种子加到 12
elif |Δ| < 0.005         → 真否证
elif not ③              → 地板不稳 ⇒ 先查管线
else                     → 未判死也未判活
```

**为什么 ③ 必须排在最后**：`Δ` 很小时 `SD_real / |Δ|` 会天然变大，
那是"Δ 小"的**后果**，不是独立的仪器问题 —— 若让 ③ 抢在前面，
一个"效应太小 ⇒ 功效不足"的结果会被误报成"测量管线有问题"。

#### 本节的离线验证（结果产生前完成）

`_l1_smoke.py` 用合成 `done` 把上表 8 条分支各走一遍，**8/8 命中**（日志 `_l1_smoke.log`）。
该自测**会删除** `dior_l1.json` / `DIOR_L1_DONE` 收尾，不留假完成标记。
（自测本身先抓出两个问题：① 我最初的合成场景没真的把 heavy 端压到地板，
分支其实没被测到；② 原代码把"SD_real 过大"归到"协议失败"，与本节不符 —— 都已修。）

**止损纪律**：①③ 任一触发即执行，不许事后改阈值。
**失败性质必须写清**：是现象被否证（效应确实更小），还是功效/协议问题。
这两者对能否发表的影响完全不同。

## 5. L1 的数据自检（不过就不许往下跑）

`dior_prep.py` 分两级，**标注级检查与图像解压解耦**：

1. `--check-ann`（零图像、零 GPU）：解析本机已有的官方 `dior_annotations_trainval.zip`
   （23,463 XML），要求 `n_box == 192,472` 且 float32 短边分桶
   `== [10,481,4456,8711,25214,24367,35541,21273,31818,40601]`（= L0 基准）。
2. `--check`（解压后）：对每张**已解出的图**，把写出的 YOLO 标签回读、换算回像素框，
   与 XML 直算的框**逐图逐框比对**（判据 = 几何量在量化容差内一致，见 §7.1）。
   另有**完整性检查**：凡解出的图都必须有对应标注（`n_no_ann == 0`，见 §7.6）。
   ⇒ 不需要"魔法常数"，因为期望值由同一次运行里的另一条路径给出。

标注源选择：**官方 VOC XML 优先**（不是下载里的 `COCO_labels.zip`），
理由：① L0 的自检基准就是在 VOC 上算的，自检才有意义；
② VOC 是 DIOR 官方格式；③ 避免引入一个未经验证的第三方转换的框约定差异。

## 6. 事先声明的局限（无论结果如何都要写进论文）

1. L1 只有 **1 个种子**，无法给出种子水平 SD；`SNR_imp` 依赖 §3.2 的导入假设。
2. L1 只在**子集**上做，不是全量 23,463 张 ——
   与 AI-TOD 的 2804 池相比，图像数少 ⇒ 训练集更小 ⇒ **绝对 mAP 不可与 AI-TOD 横向比**，
   L1 只做**相对对照**。
   （原文此处写"首个 1000 张，按 stem 排序"；该取样规则已在 §7.4 **结果产生前**改为
   **`md5(文件名)` 确定性乱序取前 2000**，规模只增不减、判据不变。）
3. DIOR 目标中位 23 px（AI-TOD 中位 10 px）⇒ 这本来就是**跨尺度边界检验**，
   若效应量更大或更小，都可归因于尺度，而不是"复现失败"。
4. L1 不含架构轴（仍为 YOLOv8n）。

## 7. 本文件写下之后的修正记录（**均不改判据**）

### 7.1 2026-10-16 18:20 — 回环自检的判据修正（抓到自己写的一个假失败陷阱）

原设计让 `dior_prep.py --check` 要求"**逐框短边分桶必须与 XML 直算完全一致**"。
实测发现这是错的：

| 事实 | 数值 |
|---|---|
| DIOR 短边**恰好落在桶边界**上的框 | **28,514 / 192,472** |
| YOLO 标签是归一化 6 位小数 ⇒ 回读引入的像素误差 | ≤ 4e-4 px |
| ⇒ 边界上的框被推过边界的概率 | 约 50% |
| 用 `round(短边)` 后再分桶 | `481/4455/8708/25218/24366/…` |
| float32 口径分桶（= L0 基准） | `481/4456/8711/25214/24367/…` |

⇒ **一个完全正确的实现也必然产生上千个分桶差异**，严格分桶相等会假失败。
判据改为"**几何量（w/h/cx/cy）在量化容差 2e-3 px 内逐框一致**"，分桶只作**报告**。
这与 `L0_VERDICT.md` §1 的 float32 发现是同一类问题的两个方向：
那边是"回读残差把框推过边界"，这边是"量化残差把框推过边界"。

另记：**244 个框的短边本身不是整数**（最大偏离 0.497）⇒ 不能假设 DIOR 全是整数框。

### 7.4 2026-10-16 18:27 — ★ 取样规则改为 md5 确定性乱序（**结果产生前**，规模只增不减）

原文 §2 写"首个 1000 张，按 stem 排序"。解压后实测发现**这个归档有块结构**，
"前 N 张排序"取到的是**块**而不是随机子集：

| 子集 | 每图目标数 | 中位短边 |
|---|---|---|
| **前 1000** | **6.02** | **24.0** |
| 其余 4,862 | 5.46 | 29.0 |
| 前 2000 | 5.73 | 27.0 |
| 前 3000 | 5.54 | 28.0 |
| 整档 5,862 | 5.56 | 28.0 |

⇒ 前 1000 张两个独立指标同向偏离（目标多 10%、目标小 20%），是**系统性块**，不是抽样噪声。
再把 N=1000 的 scan 段（250 图）展开，**只有 3 个桶满足 n ≥ 150**
（`16-24/32-64/64+`）⇒ mAP5095 只在 3 个桶上平均，太不稳。

**改动（两处，都是"变严"）**：

1. **取样 → `md5(文件名)` 确定性乱序取前 N**（与归档顺序无关，可审计、可复现）。
   实测该子集与整档的分桶比例最大偏离 **+2.7 pp**（其余桶 ≤2.0 pp），
   而"前 2000"偏离 +2.9 pp、"后 25% 作 scan"偏离 **+5.0 pp**、"系统划分（每 4 取 1）"偏离 **+6.7 pp**
   ⇒ md5 方案是本机测过的四种里最接近整档的。
2. **N 1000 → 2000、scan 250 → 500**（目标数 2,533，可用桶 6 个）。

**判据、阈值、16 条件网格、端点定义全部不变**。

运行时会把池/train/scan 三层的分桶与 `n≥150` 可用桶数打进日志（`dior_l1.py: dist_report`），
供事后审计。

### 7.5 2026-10-16 18:30 — ★ 修掉 `dior_l1.py` 的一个 stdout 崩溃（与本课题数据无关，但会挡住 L1）

`deg_ops.py:23` 与 `probe0_sr.py:24` **都**在 import 时执行

```python
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8")
```

而两处**都不保留旧 wrapper 的引用**。第二个模块被 import 时，第一个 wrapper 的引用计数归零
⇒ 被 GC ⇒ `TextIOWrapper.__del__` → `close()` → **关掉两者共享的底层 buffer**
⇒ 此后所有 `print` 报 `ValueError: I/O operation on closed file`。

实测（两种 import 顺序都炸）：

| 顺序 | 结果 |
|---|---|
| `probe0_sr` → `deg_ops` | ❌ `I/O operation on closed file` |
| `deg_ops` → `probe0_sr` | ❌ 同上 |

**修法**：在每个危险 import 前后把当时的 `sys.stdout` 钉在模块级列表里（防 GC）。
修后两种顺序都正常，`[engine] bsrgan ×4` 能打出。

`tv_sweep.py` 有同样的隐患（它自己的注释只提到"不要在这里再包装"，没解决跨模块的双重包装），
只是它的实跑环境侥幸没触发 —— **记在这里，以后写任何同时 import 这两者的脚本都要照此钉住**。

### 7.6 2026-10-16 18:47 — ★ 更正数据集构成（`val.zip` 是 5,863 张，不是 17,601 张）

原文 §5 及早期日志里出现过"有标注但无图像 **17,601** 张"这个数字，**口径错了**。
解压 `val.zip` 后核对出真实构成：

| 集合 | 图数 | 框数 | 来源 |
|---|---|---|---|
| train | 5,862 | 32,591 | `train.zip` |
| val | 5,863 | 35,434 | `val.zip` |
| **train + val** | **11,725** | **68,025** | = DIOR **官方 trainval 集** |

| 标注包合计 | — | **192,472** | `dior_annotations_trainval.zip`，23,463 XML |

⇒ 23,463 XML = 11,725（trainval）+ **11,738**（官方 test）。
之前那个 17,601 是"23,463 − 5,862"的**误减**，把 val.zip 的 5,863 张错算成"没图像"。
`dior_annotations_trainval.zip` 这个名字其实**包含 test 的标注**（不止 trainval），这是它的坑。

**新增的完整性检查**（`dior_prep.py: write_labels()` 返回 4 元组，已加）：

```python
no_ann = [stem for stem in idx if stem not in recs]
n_no_ann = len(no_ann)
log(f"     已解出但无标注 {n_no_ann:,} 张"
    + (f"  ★ 例：{sorted(no_ann)[:5]}" if n_no_ann else "  ✅"))
```
